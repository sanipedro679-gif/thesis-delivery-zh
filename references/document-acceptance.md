# 实际文档验收

记录输入 SHA-256；原件只读。修改稿独立命名 `_R01` 等，保留校徽、签字区、表头和模板分节。不能把必要的封面空字段或教师签名空间当成错误留白。检查报告与提交稿分开。

## 结构检查

在实际 DOCX 上检查，不以生成脚本或抽取文本替代：

- 正文和标题样式、直接格式、中英文字体、数字字体与字号。
- 段前段后、倍数或固定值行距、首行缩进、多余空段、样式继承。
- 表格与单元格上下内边距、条件表格样式、行高、换页与单元格宽度。
- 分节纸张与页边距、列表重启、提纲深度和标题层次。

首版 `inspect_docx.py` 自动覆盖可解析的段距/行距/字体/字号/上下内边距/页面几何、配置的文字规则和手工数字列表。自动编号显示值、缩进、复杂条件样式、主题字体、行高与分页仍须通过文档工具和页面复核。它会对部分不支持的特征报告 pending，但没有命中也不证明这些方面合格。

## 页面检查

先按会话 documents 技能尝试可用渲染器，读取失败日志。若依赖缺失且当前机器有 Word，可用本地 Word 导出副本 PDF，再用可用 PDF 工具生成页面图，记录实际采用方式。不要为转换向未经授权的在线服务上传全文。

逐页打开页面图，检查缺字、截断、重叠、表格断裂、孤立标题、异常空白及页眉页脚。逐页查看结果记录输入 DOCX 哈希、导出 PDF 哈希、渲染器、总页数、已看页码和发现。只有全部页已看且对应当前版本，才可称页面检查完成。后续改变内容或格式会使旧页面结论失效。

正文、引用编号、来源核验、论点支持、结构格式、页面查看分别记录 `pass/fail/pending/not_performed`。语义审阅不伪装成脚本实测；结构检查不能充当排版验收。交付只提供用户要求的成品和必要的状态说明，不默认附全部内部页图、台账或写作提醒。
