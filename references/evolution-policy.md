# 经验维护与版本升级

这是任务运行时执行的本地维护流程，没有后台自动运行或模型训练。每次任务开始读取状态与问题，每次确认新问题后记录。只保存最小脱敏片段，不保存完整论文、付费原文、凭证与个人封面信息。

## 范围与状态

- 项目问题：写该论文目录 `thesis-issues.jsonl` 和配置，不推广学校特定禁令。
- 用户偏好：保留适用条件；没有证据不将单次意见推广为永久要求。
- 通用经验：保存于本技能 `evolution/issues.jsonl`，经过验证后用于同类任务。

## 共性提炼

先用“什么机制失效”描述问题，再写条件化规则：要求缺少范围、材料用途不清、证据状态混用、多个表示未同步、表达功能错位、验证对象不一致等。按 [共性规则](general-principles.md) 判断归属，合并同因问题。

通用记录中的规则、修复与验收条件不携带具体项目题目、学校章数、禁用词或格式值；这些细节保留在项目记录。测试必须使用具体输入，但至少更换两组参数并有合法例外，检查规则是否依赖旧答案。测试通过只证明实现对所测机制有效，不能证明所有学科或学校都已验证。

状态为 `pending_analysis → pending_validation → active`，失效规则改为 `deprecated`。记录包括触发条件、观察失败、根因、范围、修复、例外、可观察检查和回归测试位置。已有规则复发时检查是否未加载、触发条件不完整、检查没覆盖或检查结果被忽略；相同问题不重复追加规则。

## 工具

```powershell
py -3.12 -X utf8 <技能目录>/scripts/evolve.py list
py -3.12 -X utf8 <技能目录>/scripts/evolve.py record --issue <脱敏问题.json>
py -3.12 -X utf8 <技能目录>/scripts/evolve.py transition --id <ISS-ID> --status pending_validation --note <修复说明>
py -3.12 -X utf8 <技能目录>/scripts/evolve.py transition --id <ISS-ID> --status active --note <验证结论>
py -3.12 -X utf8 <技能目录>/scripts/evolve.py release --version 1.0.1
py -3.12 -X utf8 <技能目录>/scripts/evolve.py rollback --version 1.0.0
```

问题 JSON 字段见 `templates/issue.json`。CLI 只负责技能通用库，项目问题直接写项目问题库。项目记录可用同一字段结构，不将未脱敏记录传入通用库。

工具去重的是同触发条件/失败/范围的精确匹配；语义相近问题仍须人工合并。激活时要求本地回归文件存在且实际回归通过，并保存版本与资源哈希。重新加载后如实现已变化或被恢复成旧版，`effective_status` 自动变为 `pending_validation`；应重测后激活。人工还须核对测试确实证明该规则，不以绿灯替代判断。

## 升级与恢复

小范围、原因清楚、可验证的技能内部修复可直接实施，更新入口或参考流程，并补失败案例与正常对照。改变用户偏好或扩大适用范围的规则先保持候选，有明确用户要求才升级。不会自动更改学校规则、其他技能、独立记忆、付费服务或外部发布。

发布命令实际运行回归，失败或零测试会拒绝发布；快照包括入口、参考、脚本、模板和测试，版本不覆盖。问题历史与检查证据不回滚，保留诊断过程。恢复前备份全部受管资源并检查路径及哈希；在技能自身目录内恢复，不修改论文。

恢复先在隔离副本演练；在真实技能执行时应有已授权的修复或恢复任务，不能仅为测试改动当前发布版。多进程维护用独占锁防止重写日志；锁冲突时先检查持有进程，不自动删锁。同步更新入口版本与变更原因，并运行结构校验。定期合并重复条目、废弃过时规则，保持入口短小。

至少演练：记录新反馈、去重、候选规则保留、测试通过后激活、重新进程加载、失败升级被拒、发布快照、修改后恢复、正常案例不受影响。历史稿只作检查输入，测试前后哈希一致。不要声称永不复发，只说明此次验证覆盖的情形。
